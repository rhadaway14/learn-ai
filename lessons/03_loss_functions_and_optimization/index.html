How does a model know which way to improve?

A loss function turns many mistakes into one score. A gradient estimates which direction changes that score. An optimizer uses those directions repeatedly. You will watch all three cooperate—and fail.

01

Training needs a scoreboard

A model may make hundreds or millions of predictions at once. Training needs a single number that summarizes how undesirable those predictions are. That number is the loss. Lower loss means better according to the chosen objective—not automatically better in every way humans care about.

Metaphor: a coach's scoreboard

A coach cannot improve a team by saying “do better.” A scoreboard makes one aspect of performance measurable. The team reviews the score, changes its strategy, and plays again. Training follows the same cycle with predictions, loss, and parameter updates.

Where the metaphor stops: a loss function is an exact mathematical rule. It optimizes only what was encoded, so a falling score can still hide unfairness, data leakage, or the wrong business behavior.

Prediction

What the current model produces.

“Delivery will take 42 minutes.”

Error

The difference between prediction and truth.

Actual 50 − predicted 42 = 8 minutes.

Loss

A rule that converts one or more errors into a penalty.

May punish large misses especially strongly.

Objective

The quantity training is instructed to minimize or maximize.

Often average loss plus other penalties.
Loss is not the same as an evaluation metric. A differentiable training loss helps parameters move. A business metric determines whether the resulting system is useful. A fraud model might train with cross-entropy but be judged by dollars prevented, false declines, recall, latency, and fairness.

02

Different losses define different priorities

Choosing a loss is not clerical work. It tells training which mistakes deserve the strongest response. We will compare three common choices.

REGRESSION

Mean Absolute Error

Take the absolute size of every error, then average. A miss of 8 contributes 8.

Steady penaltyOften more resistant to extreme outliers.

REGRESSION

Mean Squared Error

Square every error, then average. A miss of 8 contributes 64.

Large misses dominateSmooth and convenient for gradient methods.

CLASSIFICATION

Cross-entropy

Penalize probability assigned away from the correct class.

Confidently wrong hurtsRewards calibrated probability for the true answer.
Metaphor: different late-fee policies

MAE charges one dollar for every minute late. MSE charges the square of minutes late, so one disastrous delay can outweigh many small delays. Neither policy is universally correct; the appropriate rule depends on the real cost of being wrong.

Where the metaphor stops: losses operate on model outputs and may have mathematical properties chosen for optimization as well as business meaning.

Cross-entropy asks: how much probability reached the correct answer?

For one correct class, the loss is the negative natural logarithm of the probability assigned to that class. You do not need logarithm fluency yet; notice its behavior. Giving the correct answer 90% probability produces a small penalty. Giving it 1% produces a very large penalty.

03

A gradient describes the local slope

Imagine loss as height on a landscape and a model parameter as your horizontal position. The gradient answers two local questions: which direction is uphill, and how steep is it here? To reduce loss, move in the opposite direction.

Metaphor: hiking downhill in fog

You cannot see the entire mountain, but you can feel the slope under your feet. If the ground rises to your right, step left. A steeper slope suggests the loss changes rapidly with position.

Where the metaphor stops: real models have millions or billions of parameter directions, the landscape changes by direction, and optimization uses numeric gradients rather than human balance.
Negative gradient

Loss falls as the parameter moves right, so reducing loss requires moving right.

Gradient near zero

The surface is locally flat. You may be near a minimum, maximum, saddle, or plateau.

Positive gradient

Loss rises as the parameter moves right, so reducing loss requires moving left.

How can we check a gradient?

An analytical gradient comes from differentiation rules. A finite-difference estimate nudges the parameter slightly left and right, measures both losses, and divides the loss change by the distance. It is like estimating a road's slope from two nearby elevation readings.

estimated slope = (right loss − left loss) ÷ distance between the two points

Go deeper: must every loss be differentiable everywhere?

Gradient methods need a usable slope at the current point, but a loss does not have to be perfectly smooth everywhere. MAE has a sharp corner when error is zero. Libraries commonly use a defined subgradient at that corner. Neural networks also contain piecewise operations such as ReLU.

The practical requirement is that the training system can produce useful update directions for the operations it encounters. Smooth losses often make optimization easier, but “not differentiable at one point” does not automatically make a loss unusable.

Finite differences are a diagnostic, not the normal training method. Checking every parameter with extra forward calculations is far too expensive for large networks. Backpropagation, taught later, computes analytical gradients efficiently.

04

Optimization repeats small evidence-based updates

Gradient descent changes a parameter by subtracting the gradient multiplied by a learning rate. The gradient supplies direction and local sensitivity. The learning rate controls how much of that proposed direction to use.

new weight = old weight − learning rate × gradient

One complete update

At weight −1, our loss is 25 and gradient is −10. With learning rate 0.15:

new weight = −1 − (0.15 × −10) = 0.5

The weight moves right toward 4. The new loss is (0.5 − 4)² = 12.25, lower than 25.

Metaphor: adjusting a shower

The gradient says whether the water is too hot or too cold and how sensitive the current setting seems. The learning rate determines how far you turn the handle. Tiny turns are safe but slow; a huge turn can overshoot and alternate between extremes.

Where the metaphor stops: optimization can have many parameters, noisy gradient estimates, momentum, adaptive step sizes, and complex surfaces.

05

How much data should estimate each update?

A gradient calculated from all training examples is usually stable but potentially expensive. One example is cheap but noisy. A mini-batch uses a manageable subset and is the standard compromise for neural-network training.

STEP

One parameter update

One batch produces a gradient and the optimizer changes the parameters once.

EPOCH

One pass through the training set

With 12 examples, batch size 4 creates 3 steps per epoch. Batch size 1 creates 12.

Metaphor: deciding from customer feedback

Reading every survey before making any change gives a stable overview but takes time. Reacting to one survey is fast but erratic. Reviewing groups of 32 or 128 surveys provides frequent, reasonably stable updates.

Where the metaphor stops: training examples contribute mathematical gradients, and hardware efficiency strongly influences practical batch size.

GRADIENT CHARACTERStable

Full-batch descent

Useful for small datasets or deterministic analysis. Each update waits for every example.

Stochastic descent

Updates after one example. Noise can help exploration but produces an erratic path and inefficient hardware use.

Mini-batch descent

Balances update frequency, gradient quality, memory, and accelerator throughput.

Batch size changes the optimization process. Doubling it does more than change memory use. It changes gradient noise, update count, hardware utilization, and sometimes the learning rate that works well.
