Backpropagation From Scratch

Backpropagation starts at one loss value and moves backward through the operations that produced it. At each step, it combines an incoming gradient with a local derivative to calculate responsibility.

01

A forward pass produces a prediction; backpropagation assigns responsibility

Training needs more than knowing that loss is high. It needs the derivative of loss with respect to every learnable parameter: how a tiny change to that parameter would change the final loss, with other current values held fixed.

FORWARD PASS

What value does the graph produce?

Use current inputs and parameters to calculate intermediate values, prediction, and loss.

BACKWARD PASS

How sensitive is loss to each value?

Traverse dependencies in reverse and calculate one gradient for every value that needs it.

Metaphor: tracing a final invoice backward

A project total comes from subtotals, quantities, and rates. To understand how changing one rate affects the final invoice, trace that rate's contribution through each subtotal to the total.

Where the metaphor stops: backpropagation computes local derivatives rather than blame or causal responsibility, and all sensitivities are evaluated at the current numerical point.

Value

A number produced during the forward pass.

Pre-activation p = 7.

Local derivative

How an operation's output changes with one direct input.

For y = p², dy/dp = 2p.

Upstream gradient

Sensitivity already arriving from later in the graph.

How loss changes with y.

Parameter gradient

Final sensitivity of loss to a learned parameter.

Used by the optimizer.
Read the calculus notation aloud: a derivative is the local slope or sensitivity introduced in Lesson 3. Read dy/dx as “the derivative of y with respect to x”—how much y changes when x changes a little. Use d when the expression follows one input. Read ∂y/∂x as “the partial derivative of y with respect to x.” The symbol ∂ means we vary x while holding the other current inputs fixed. In the trace, ∂L/∂W means how the loss L responds to each element of weights W.

PREREQUISITE CHECK

If increasing a weight slightly increases loss, which direction should gradient descent move that weight?

03

The chain rule multiplies sensitivity along a path

If x changes u, and u changes y, then x changes y through both links. The total local effect is the product of the two derivatives.

Metaphor: connected gear ratios

If one gear turns twice for each input turn and the next turns three times for each turn it receives, the final gear turns six times per input turn: 2 × 3.

Where the metaphor stops: derivatives can vary with the current values, be negative or zero, and graphs can branch and merge rather than forming one physical gear chain.

Chain rule in words, numbers, then notation

Let u = 2x + 1 and y = u². At x = 3, u = 7. A small change in x changes u by factor 2. A small change in u changes y by factor 2u = 14. Therefore y changes with x by factor 14 × 2 = 28.

dy/dx = dy/du × du/dx = 14 × 2 = 28

04

Every operation acts like a local gradient gate

During the backward pass, an operation receives an upstream gradient and multiplies it by its local derivative. The result is the downstream gradient for each input.

Add

Passes the upstream gradient unchanged to each input.

Local derivative: 1

Multiply

Sends the upstream gradient times the other input.

For m = xw: dm/dx = w

Square

Sends the upstream gradient times twice its input.

For y = p²: dy/dp = 2p

Activation

Scales or blocks the signal using its local slope.

ReLU slope is 0 or 1 away from zero

05

Gradients multiply along paths and add across paths

When one value influences the loss through several branches, its total gradient is the sum of every path's contribution. This is not optional bookkeeping: it is the multivariable chain rule.

Metaphor: several tributaries meeting one river

Each downstream route returns a contribution to the same upstream location. The total arriving flow is the sum of the tributaries.

Where the metaphor stops: gradient contributions can be negative and cancel, and they represent local sensitivity rather than physical material.

Two meanings of accumulation: contributions add within one graph because a value has multiple paths. Autograd systems may also add gradients across separate backward calls because gradient buffers are stateful. The causes are different, even though both use addition.

06

Reverse-mode differentiation fits one loss and many parameters

A neural network may contain millions or billions of parameters but normally trains from one scalar loss per batch. Reverse mode starts with the loss derivative 1 and computes all parameter gradients in one backward traversal.

Forward mode

Efficient when there are few inputs and many outputs. It carries the effect of selected inputs forward.

Reverse mode

Efficient when there is one or a few outputs and many inputs. It carries one loss sensitivity backward to all parameters.

Tensor gradients preserve parameter shapes

If weights W are shaped (10, 64), the gradient ∂L/∂W is also (10, 64). Each weight gets its own copy of the same upstream-gradient × local-derivative calculation.

One numeric tensor gradient

Let input x = [2, 3, 4] feed two outputs through a 3 × 2 weight matrix. If the arriving output gradient is [5, 6], each weight gradient is input value × arriving output gradient:

∂L/∂W = [[10, 12], [15, 18], [20, 24]]

The result is 3 × 2, exactly like W. Row 1 uses input 2, row 2 uses input 3, and row 3 uses input 4.

Backpropagation calculates gradients; the optimizer applies updates. Backward does not itself decide the learning rate or change parameters. That separation is why the training-loop order matters.
Go deeper: Jacobian-vector products without building a giant Jacobian

A vector-valued operation has a Jacobian containing all local output-to-input derivatives. Reverse mode multiplies the arriving gradient vector by that local Jacobian as it traverses the graph. Frameworks compute this vector–Jacobian product directly rather than materializing an enormous matrix.

07

Gradient buffers are state and must be managed deliberately

Many autograd frameworks add each backward result into a parameter's existing gradient buffer. This supports intentional accumulation across microbatches or objectives. It also creates a quiet bug when stale gradients are not cleared.

    Stop-gradient deliberately cuts a backward path

    A detach or stop-gradient operation keeps a value in the forward calculation but treats it as constant during backward traversal. This is useful for frozen targets, teacher outputs, or carefully designed objectives. Applied accidentally, it silently prevents earlier parameters from learning.

    Engineer deep dive · reverse mode and gradient failure

    Turn the concept into an engineering contract

    Start by naming the input, output, units, axes, valid ranges, and lifecycle boundary for every value involved. Record which facts exist at training time, prediction time, and only after the outcome. Add invariants that a program or reviewer can check: shapes agree, values are finite, identifiers do not cross split boundaries, and repeated execution with the same seed stays within a declared tolerance. A successful calculation is not enough; the result must retain its meaning at every interface.

    Verify mechanics with a known-answer case

    Build the smallest example that can be calculated independently, then preserve its inputs and expected intermediate values as a regression test. Check more than the final number. Inspect the state before the operation, the state immediately afterward, and the evidence used by the next operation. Compare a hand-worked case, a trusted reference implementation, and the production path. When they disagree, change one factor at a time. This separates a mathematical defect from indexing, reduction, precision, initialization, or data-contract defects.

    Run a controlled failure experiment

    Write a prediction before changing anything: name the control, the expected failure signal, and the recovery condition. Perturb one assumption deliberately, such as scale, ordering, sample composition, initialization, or a boundary value. Keep the original evidence and configuration so the comparison remains causal. The system should fail visibly and safely rather than produce a plausible but invalid answer. Restore the known-good state, rerun the same verification, and retain both the failure and recovery records.

    Instrument the mechanism, not only the outcome

    Aggregate quality metrics can improve while an internal mechanism is failing. Capture distributions and counts for the quantities this section introduces, segmented by meaningful slices and accompanied by sample size. Track missing and nonfinite values, extrema, representative quantiles, drift from a reference run, and the rate at which guardrails activate. Establish an expected range from validation evidence before choosing alert thresholds. Logs should identify the dataset, configuration, model or artifact version, and execution stage without exposing sensitive records.

    Reason about scale and operational cost

    Estimate how work and memory grow with examples, features, parameters, and any pairwise dimensions. Distinguish persistent state from temporary activations and useful compute from data movement, serialization, and synchronization. Measure representative workloads rather than extrapolating from one tiny example. State the latency, throughput, memory, and numerical precision budget, then identify which approximation or batching decision could violate the learning contract. Performance changes require the same correctness evidence as algorithm changes.

    Define promotion, rollback, and ownership

    A reviewable artifact includes data lineage, configuration, environment, seeds, assumptions, acceptance thresholds, known limitations, and the exact command or interaction that reproduces the result. Promotion should require protected evaluation evidence and an explicit owner. Rollback should name a previously verified artifact and the signal that triggers restoration. Monitor the deployment population for the assumptions made here; when those assumptions stop holding, route the system to a safe behavior and reopen the engineering decision instead of silently trusting yesterday's evidence.

    Prerequisites: the Lesson 3 gradient direction and learning-rate model plus the Lesson 6 forward graph, activation, parameter, and loss vocabulary.

    Reverse-mode differentiation propagates vector–Jacobian products from one scalar loss to many parameters without materializing full Jacobians. Contributions add at branches and local derivatives multiply along chains, enabling efficient learning while creating vanishing and exploding paths.

    Saved forward context consumes memory; mixed precision needs scaling; large batches may use accumulation; distributed jobs synchronize gradients. Stale gradients, detached tensors, mutation, saturation, and incorrect reduction scaling can all mislead updates.

    Trace vector–Jacobian products, not giant Jacobian matrices

    Reverse mode receives an upstream sensitivity and multiplies it by each operation's local derivative. Frameworks compose these vector–Jacobian products backward, so one scalar loss can differentiate millions of parameters without materializing a full derivative matrix. At a branch, every downstream contribution must be summed. A gradient ledger should record tensor shape, reduction rule, and incoming path; the expected final shape can still conceal a missing branch or an unintended mean-versus-sum factor.

    Normalize accumulation deliberately

    If four micro-batches emulate one batch, divide each loss by four before backward or divide accumulated gradients once before the update. Doing neither makes the update four times larger; doing both makes it four times smaller. In distributed execution, verify whether collectives sum or average and account for unequal worker batch sizes. Monitor per-layer norm, zero-gradient fraction, nonfinite count, and update-to-weight ratio. Clipping can contain an incident, but frequent clipping is evidence to investigate loss scale, learning rate, data, or architecture.
