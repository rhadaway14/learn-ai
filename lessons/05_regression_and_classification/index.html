Regression and Classification

Before choosing an algorithm, decide what decision the prediction will support. Regression estimates a number. Classification estimates which category applies. Evaluation tells us whether either result is useful outside the training data.

01

Supervised learning learns from examples with known answers

Each historical example contains information available at prediction time and a known outcome. Training searches for a mapping from the information to the outcome. The learned model then estimates outcomes for new examples whose answers are not yet known.

Metaphor: an apprentice reviewing completed jobs

An apprentice studies old project intake forms alongside final effort and delivery results. Over time, the apprentice notices patterns and estimates a new project from its intake form.

Where the metaphor stops: a model does not understand a project as a human does. It optimizes numerical patterns in the examples, including accidental and harmful patterns.
Labeled examples→Training→Learned mapping→Prediction for a new example

Example

One row or case the model can learn from.

One completed delivery project.

Feature

An input available when prediction happens.

Document count, integrations, deadline.

Label or target

The correct outcome the model should learn to estimate.

Actual effort or late/on-time result.

Prediction

The model's estimated target for a new case.

620 hours or 72% late risk.
The prediction-time rule: a feature is valid only if it will genuinely exist at the moment the real prediction must be made. Information created afterward is leakage, even when it makes validation look excellent.

02

The target determines whether the task is regression or classification

REGRESSION

Predict a numeric amount

Hours, latency, temperature, revenue, or remaining useful life. The output can vary along a numeric scale.

CLASSIFICATION

Predict a category

Late/on time, fraud/not fraud, document type, or one of several routing destinations. The model often produces class scores or probabilities before a category is chosen.

Metaphor: measuring versus sorting

Regression is like reading a measuring tape: the answer is an amount. Classification is like sorting packages into labeled destinations: the answer is a category.

Where the metaphor stops: classifiers commonly output continuous scores, and a product rule converts those scores into actions. Categories may also overlap or have hierarchy.

TASK FRAMING LAB

Choose the target type—not the algorithm name

For each business question, decide whether the required output is numeric or categorical.

Predict next month's cloud spend in dollars

Route a ticket to billing, security, or support

Estimate API latency in milliseconds

Decide whether a migration needs executive review

Task framing is a product decision. “Predict delivery risk” is incomplete. Specify the unit of prediction, target, time horizon, decision, acceptable errors, and information available at prediction time.

03

Regression estimates a position on a numeric scale

Linear regression from Lesson 1 is one regression method, but regression is the broader task. A model can use many features and nonlinear relationships while still predicting a number.

Metaphor: drawing a route through landmarks

Historical examples are landmarks. A regression model draws a route representing the pattern and uses that route to estimate locations between or near known landmarks.

Where the metaphor stops: data can be noisy, features can interact, and predictions far beyond observed data are extrapolations—not trustworthy extensions of a road.

A residual is what the model left unexplained

This course uses the Lesson 1 convention: residual equals prediction minus actual label. A negative residual means the model predicted too low; a positive residual means it predicted too high. Some texts reverse the order, so always check the stated convention.

predicted 590 hours − actual 640 hours = −50-hour residual

MODEL COMPLEXITY LAB

Compare a baseline, a useful trend, and an overfit curve

Training points are completed projects; test points represent unseen projects. A good model must generalize beyond the examples it fit.

TRAIN MAE

TEST MAE

TEST RMSE

TEST R²

MAE

Average absolute error. “Predictions miss by 0.8 units on average.” Every unit of error counts linearly.

RMSE

Square errors, average them, then take the square root. Large misses receive extra weight while the final result returns to target units.

R²

Compares the model with predicting the target mean. 1 is perfect, 0 matches that baseline, and a negative value is worse than the baseline.

Always establish a baseline. A sophisticated regression model that cannot beat “predict the training mean every time” has not demonstrated useful learning.

04

Classification separates categories using evidence

A binary classifier often produces a score between 0 and 1 for the positive class. A threshold converts that score into a category or action. The model score and the action rule are related, but they are not the same thing.

Metaphor: airport security screening

A risk score orders cases from less concerning to more concerning. A checkpoint threshold decides who receives additional screening. Moving the checkpoint changes both missed risks and unnecessary reviews.

Where the metaphor stops: model scores are only probabilities when calibration supports that interpretation, and real decisions can use multiple thresholds, queues, or human review.

Score

A continuous model output used to rank evidence for a class.

Threshold

The operating rule above which a score becomes a positive decision.

Decision boundary

The location in feature space where the predicted decision changes category.

Logistic regression turns a logit into a bounded output

Linear regression can produce any number. Logistic regression first combines features into an unrestricted weighted score called a logit, commonly written z. The sigmoid maps that logit through an S-shaped curve. Very negative logits approach 0, very positive logits approach 1, and a logit of 0 becomes 0.5.

features and weights → logit z → sigmoid → value between 0 and 1 → threshold → class decision
Go deeper: the sigmoid equation

The question is: how can an unbounded logit become a value between 0 and 1?

For a logit of 0, the calculation is 1 ÷ (1 + 1), which equals 0.5.

p = 1 ÷ (1 + e−z)

z is the logit, e is the natural exponential constant, and p is the bounded output. Logistic regression learns the feature weights; the product team chooses how the output drives action. A sigmoid output is not automatically a calibrated probability; calibration must be checked on representative held-out data.

Fraud review

Rank transactions by risk and route a manageable high-risk set to review.

Content moderation

Separate allowed, review, and block actions using policy-specific thresholds.

Operational routing

Assign incidents, documents, or requests to a destination category.

05

A confusion matrix names all four classification outcomes

“Positive” means the class or action the system is trying to detect; it does not mean good. “True” means the decision matched reality. Combine those words and every prediction belongs to one of four cells.

True positive

Predicted late; actually late.

False positive

Predicted late; actually on time.

False negative

Predicted on time; actually late.

True negative

Predicted on time; actually on time.

Metaphor: a smoke alarm

Precision asks how often alarms correspond to a real fire. Recall asks how many real fires the alarm detects. Sensitivity is another name for recall. Specificity asks how many non-fires remain quiet.

Where the metaphor stops: business cases can have delayed or uncertain labels, more than two classes, and costs that vary by individual example.

Accuracy

Correct decisions ÷ all decisions.

Useful when classes and error costs are reasonably balanced.

Precision

True positives ÷ all predicted positives.

When the model raises an alert, how often is it right?

Recall

True positives ÷ all actual positives.

Of the cases we needed to catch, how many did we catch?

F1 score

Harmonic balance of precision and recall.

Useful summary, but it still hides the specific error costs.

The accuracy trap

Suppose only 10 of 1,000 projects are late. A model that predicts “on time” for every project gets 990 correct.

99% accuracy0% recall10 late projects missed

The model looks excellent by accuracy and is useless for detecting late projects. Always inspect class balance, the confusion matrix, and decision costs.

06

The threshold is where model evidence becomes a product decision

Lowering the threshold usually catches more positives and creates more false alarms. Raising it usually reduces false alarms and misses more positives. The correct operating point depends on capacity, risk, and the relative cost of each error.

    07

    Evaluation must simulate the prediction the system will make in reality

    Training setLearn parameters

    The model sees these labels while fitting patterns.

    Validation setChoose design and threshold

    Compare models and operating points without touching the final test.

    Test setEstimate final generalization

    Use once the choices are frozen; it is not a reusable tuning dashboard.

    Metaphor: studying, taking practice exams, then sitting the final

    Training is studying examples. Validation is a practice exam used to adjust strategy. The test set is the final estimate after the strategy is fixed.

    Where the metaphor stops: datasets are not automatically independent, production changes over time, and repeated test-set use quietly turns the final into another practice exam.

    Leakage lets the model peek at an answer it will not have in production

    Leakage can enter through future information, duplicated entities across splits, preprocessing fit on all data, or repeated threshold tuning against the test set.

    LEAKAGE REVIEW

    Mark each evaluation design as safe or leaking

    Use the final delay-reason code to predict lateness at intake

    Fit preprocessing on training data, then apply it unchanged to validation

    Randomly split repeated records from the same customer across train and test

    Keep changing the threshold until test-set F1 looks best

    ROC and precision–recall curves compare thresholds

    ROC curve

    Plots true-positive rate (recall) against false-positive rate as the threshold moves. ROC AUC summarizes ranking across thresholds, not calibration or the best business threshold.

    Precision–recall curve

    Plots precision against recall as the threshold moves. It focuses on positive-class performance and is often more revealing when positives are rare.

    Split like production. Use chronological splits when predicting the future, group splits when the same customer or device repeats, and stratification when rare classes must appear in each partition. Then report slice metrics and uncertainty—not only one aggregate score.

    Engineer deep dive · scores, decisions, and release evidence

    Turn the concept into an engineering contract

    Start by naming the input, output, units, axes, valid ranges, and lifecycle boundary for every value involved. Record which facts exist at training time, prediction time, and only after the outcome. Add invariants that a program or reviewer can check: shapes agree, values are finite, identifiers do not cross split boundaries, and repeated execution with the same seed stays within a declared tolerance. A successful calculation is not enough; the result must retain its meaning at every interface.

    Verify mechanics with a known-answer case

    Build the smallest example that can be calculated independently, then preserve its inputs and expected intermediate values as a regression test. Check more than the final number. Inspect the state before the operation, the state immediately afterward, and the evidence used by the next operation. Compare a hand-worked case, a trusted reference implementation, and the production path. When they disagree, change one factor at a time. This separates a mathematical defect from indexing, reduction, precision, initialization, or data-contract defects.

    Run a controlled failure experiment

    Write a prediction before changing anything: name the control, the expected failure signal, and the recovery condition. Perturb one assumption deliberately, such as scale, ordering, sample composition, initialization, or a boundary value. Keep the original evidence and configuration so the comparison remains causal. The system should fail visibly and safely rather than produce a plausible but invalid answer. Restore the known-good state, rerun the same verification, and retain both the failure and recovery records.

    Instrument the mechanism, not only the outcome

    Aggregate quality metrics can improve while an internal mechanism is failing. Capture distributions and counts for the quantities this section introduces, segmented by meaningful slices and accompanied by sample size. Track missing and nonfinite values, extrema, representative quantiles, drift from a reference run, and the rate at which guardrails activate. Establish an expected range from validation evidence before choosing alert thresholds. Logs should identify the dataset, configuration, model or artifact version, and execution stage without exposing sensitive records.

    Reason about scale and operational cost

    Estimate how work and memory grow with examples, features, parameters, and any pairwise dimensions. Distinguish persistent state from temporary activations and useful compute from data movement, serialization, and synchronization. Measure representative workloads rather than extrapolating from one tiny example. State the latency, throughput, memory, and numerical precision budget, then identify which approximation or batching decision could violate the learning contract. Performance changes require the same correctness evidence as algorithm changes.

    Define promotion, rollback, and ownership

    A reviewable artifact includes data lineage, configuration, environment, seeds, assumptions, acceptance thresholds, known limitations, and the exact command or interaction that reproduces the result. Promotion should require protected evaluation evidence and an explicit owner. Rollback should name a previously verified artifact and the signal that triggers restoration. Monitor the deployment population for the assumptions made here; when those assumptions stop holding, route the system to a safe behavior and reopen the engineering decision instead of silently trusting yesterday's evidence.

    Prerequisites: confusion-matrix counts, precision, recall, probability calibration, and train/validation/test boundaries from Lessons 1–5.

    Training objectives, ranking metrics, probability calibration, and operating thresholds answer different questions. Cross-entropy can learn scores; precision–recall curves assess ranking; calibration compares probabilities with frequencies; a threshold creates an action under cost and capacity constraints. None substitutes for the others.

    Evaluation must mirror time, entity, and prevalence boundaries. Leakage can make a useless system look exceptional, accuracy can hide rare-class failure, and repeated test-set tuning quietly converts the test into validation data.

    Architecture review question: Which metric, threshold, and slice evidence would justify waking an on-call engineer?
