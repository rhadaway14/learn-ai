01

Programming rules versus learning patterns

In ordinary programming, a person writes the rules. If a package weighs less than five pounds, charge one price; otherwise, charge another. The computer follows instructions that already exist.

TRADITIONAL PROGRAMMING

People provide the relationship

Rules+Data→Answer

Best when the rules are known and can be stated precisely.

MACHINE LEARNING

Examples reveal the relationship

Examples+Answers→Model

Useful when a pattern exists but writing every rule would be difficult.

Learning does not mean understanding like a person. Here, learning means finding numerical settings that make predictions less wrong across many examples.

02

The vocabulary, without the fog

Feature

Information given to the model. In our lab, the feature is a number called x.

Example: square footage

Label

The correct answer in a training example. We call it y.

Example: actual sale price

Model

A mathematical rule that turns an input into a prediction.

Here: a movable straight line

Prediction

The answer produced by the model. It may differ from the known label.

Written as y-hat

Training

Repeatedly adjusting the model using examples with known answers.

The model is changing

Inference

Using a trained model to predict an answer for a new input.

The model is no longer changing

03

Our model is a line we can move

A straight line is enough to introduce learning. Its equation is shown below, but read it as a sentence before treating it as mathematics.

prediction = weight × input + bias
ŷ = w × x + b

Weight (w) tilts the line

If the weight is 3.5, increasing the input by 1 increases the prediction by 3.5. A negative weight tilts downward.

Bias (b) moves the line

The bias is the prediction where the input is zero. Increasing it moves the entire line upward without changing its tilt.

Worked example

If the weight is 3.5, the input is 4, and the bias is 2:

prediction = 3.5 × 4 + 2prediction = 14 + 2prediction = 16
Parameters versus controls: weight and bias are parameters the model learns. Settings such as learning rate and number of examples are experiment controls chosen by a person.

How do we measure “wrong”?

For each example, the model makes a prediction. The difference between the prediction and the correct label is the residual error.

A dataset contains many errors, so we need one summary score. Mean squared error (MSE) does this in three understandable steps:

  1. 1
    Find every error

    Subtract the correct answer from each prediction.

  2. 2
    Square each error

    This makes every contribution positive and makes large mistakes matter more.

  3. 3
    Take the average

    One number now summarizes the model's error across all examples.

MSE = average of all (prediction − correct answer)²

Lower is better. Zero would mean every prediction exactly matched its label. MSE uses squared units, so compare it between runs on the same kind of data—not as if it were an ordinary error amount.

05

How does the model improve?

Imagine making a tiny change to the weight. If the loss becomes larger, that was the wrong direction. If it becomes smaller, that was the right direction. A gradient captures both the direction and the local sensitivity of loss to a parameter.

+

Positive gradient

Increasing the parameter would increase loss, so training decreases the parameter.

−

Negative gradient

Increasing the parameter would decrease loss, so training increases the parameter.

≈0

Near-zero gradient

A small local change has little effect. The model may be near the best setting available.

Gradient descent repeats this adjustment for both weight and bias. The learning rate controls how large each adjustment is.

tiny

Too small

Reliable but painfully slow.

balanced

Useful

Moves steadily toward lower loss.

huge

Too large

Overshoots and may become unstable.

The key idea: the gradient does not reveal the final answer. It gives a useful next step. Learning emerges from taking many such steps.

06

Why hide some data from training?

If you study using an answer key and then take a test containing the same questions, a perfect score proves very little. Models have the same problem.

80%Training dataUsed to adjust weight and bias
20%Test dataHidden until final evaluation

Generalization means performing well on new examples, not merely the examples used during training. Allowing test information to affect training is called data leakage; it makes results look better than they really are.
