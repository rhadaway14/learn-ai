01

Programming rules versus learning patterns

In ordinary programming, a person writes the rules. If a package weighs less than five pounds, charge one price; otherwise, charge another. The computer follows instructions that already exist.

TRADITIONAL PROGRAMMING

People provide the relationship

Rules+Data→Answer

Best when the rules are known and can be stated precisely.

MACHINE LEARNING

Examples reveal the relationship

Examples+Answers→Model

Useful when a pattern exists but writing every rule would be difficult.

Learning does not mean understanding like a person. Here, learning means finding numerical settings that make predictions less wrong across many examples.
Go deeper: AI, machine learning, and deep learning

Artificial intelligence is the broadest category. It includes any engineered approach intended to perform tasks associated with intelligent behavior, including rules, search, planning, optimization, and learning.

Machine learning is one approach inside AI. Instead of specifying every decision rule, engineers define a learning objective and use examples to estimate a useful model.

Deep learning is a family of machine-learning techniques based on neural networks with many layers. Large language models are deep-learning systems, but AI is much larger than language models.

The boundaries are about mechanisms, not how impressive a product appears. A complex rules engine is AI without machine learning; a tiny regression line is machine learning without deep learning.

Go deeper: supervised learning and regression

This lesson uses supervised learning because every training example contains both an input and a known correct answer. The known answer provides feedback.

It is a regression task because the model predicts a continuous numeric quantity. Predicting a named category is classification; discovering unlabeled groupings is clustering; choosing actions from rewards is reinforcement learning.

These labels describe the structure of the learning problem. They help engineers choose suitable models, losses, data, and evaluation metrics.

02B

Examples are the model's evidence

One example is one observation: an input paired with its correct answer. A dataset is a collection of examples. The model is not shown an abstract rule such as “multiply by 3.5 and add 2.” It must estimate the pattern that best accounts for the examples it receives.

Representative data

The examples should resemble the situations where the model will be used. A house-price model trained in one city may not transfer to another where location, construction, and market behavior differ.

Sample size

More examples can make an estimate more stable, but quantity cannot repair systematically biased or irrelevant data.

Noise

Two similar inputs may have different answers because important influences are missing, measurements are imperfect, or reality contains randomness.

Data is not neutral evidence. How it was collected, what it excludes, when it was observed, and how labels were produced all shape what the model can learn.

03

Our model is a line we can move

A straight line is enough to introduce learning. Its equation is shown below, but read it as a sentence before treating it as mathematics.

prediction = weight × input + bias
ŷ = w × x + b

Weight (w) tilts the line

If the weight is 3.5, increasing the input by 1 increases the prediction by 3.5. A negative weight tilts downward.

Bias (b) moves the line

The bias is the prediction where the input is zero. Increasing it moves the entire line upward without changing its tilt.

Worked example

If the weight is 3.5, the input is 4, and the bias is 2:

prediction = 3.5 × 4 + 2prediction = 14 + 2prediction = 16

The positive weight tilts the line upward. A zero bias means the line crosses the vertical axis at zero.

Parameters versus controls: weight and bias are parameters the model learns. Settings such as learning rate and number of examples are experiment controls chosen by a person.
Go deeper: parameters, hyperparameters, and model capacity

Parameters are internal numeric settings estimated during training. This line has only two. A neural network may have billions.

Hyperparameters shape the training process or model design and are selected outside ordinary training. Learning rate and number of layers are examples.

Capacity describes the range of relationships a model can represent. Changing this line's parameters produces different lines, but never a curve. The parameters choose a member of the model family; they do not change the family itself.

How do we measure “wrong”?

For each example, the model makes a prediction. The difference between the prediction and the correct label is the residual error.

A dataset contains many errors, so we need one summary score. Mean squared error (MSE) does this in three understandable steps:

  1. 1
    Find every error

    Subtract the correct answer from each prediction.

  2. 2
    Square each error

    This makes every contribution positive and makes large mistakes matter more.

  3. 3
    Take the average

    One number now summarizes the model's error across all examples.

MSE = average of all (prediction − correct answer)²

Lower is better. Zero would mean every prediction exactly matched its label. MSE uses squared units, so compare it between runs on the same kind of data—not as if it were an ordinary error amount.

Go deeper: loss versus evaluation metrics

The loss is the quantity optimization attempts to reduce. An evaluation metric is a measure people use to judge whether the result serves its purpose. They may be the same, but often are not.

MSE is smooth and strongly penalizes large errors, which helps optimization. A business may prefer mean absolute error because it is easier to interpret in the target's original units. Safety, fairness, latency, and cost may require additional metrics that no single loss captures.

05

How does the model improve?

Imagine making a tiny change to the weight. If the loss becomes larger, that was the wrong direction. If it becomes smaller, that was the right direction. A gradient captures both the direction and the local sensitivity of loss to a parameter.

+

Positive gradient

Increasing the parameter would increase loss, so training decreases the parameter.

−

Negative gradient

Increasing the parameter would decrease loss, so training increases the parameter.

≈0

Near-zero gradient

A small local change has little effect. The model may be near the best setting available.

Gradient descent repeats this adjustment for both weight and bias. The learning rate controls how large each adjustment is.

tiny

Too small

Reliable but painfully slow.

balanced

Useful

Moves steadily toward lower loss.

huge

Too large

Overshoots and may become unstable.

The key idea: the gradient does not reveal the final answer. It gives a useful next step. Learning emerges from taking many such steps.

Go deeper: what “local” means

A gradient describes the slope of the loss at the model's current parameter values. It is local because the landscape may look different after the parameters move.

For this simple line with mean squared error, the loss surface is shaped like a bowl with one best bottom. Deep neural networks have vastly more dimensions and more complicated surfaces, but optimizers still use local gradient information to choose updates.

06

Why hide some data from training?

If you study using an answer key and then take a test containing the same questions, a perfect score proves very little. Models have the same problem.

80%Training dataUsed to adjust weight and bias
20%Test dataHidden until final evaluation

Generalization means performing well on new examples, not merely the examples used during training. Allowing test information to affect training is called data leakage; it makes results look better than they really are.

Go deeper: underfitting, overfitting, and distribution shift

Underfitting occurs when the model or training process is too limited to capture the useful pattern. A straight line applied to strongly curved data is one example.

Overfitting occurs when a model adapts too specifically to training details and performs worse on new examples. Larger capacity, small datasets, leakage, and excessive tuning can increase the risk.

Distribution shift occurs when future inputs differ meaningfully from the training data. Even a model that generalized well during development may degrade when the population, environment, or behavior changes.
